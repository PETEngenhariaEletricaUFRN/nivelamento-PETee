Exercícios - Comunicação e IoT

Esta lista tem 14 exercícios sobre comunicação e Internet das Coisas (IoT). Você vai da comunicação entre dois pinos do próprio ESP32 até redes sem fio de longo alcance, passando por WiFi, Bluetooth, MQTT e transmissão de vídeo.

🛠 Requisitos e Materiais​

  • ESP32 DEVKIT (estoque: 5), ESP32 CAM (estoque: 6) e cabo USB
  • Arduino IDE ou PlatformIO com o pacote esp32 by Espressif (versão 3.x)
  • Rede WiFi para os exercícios de conexão
  • Um broker MQTT (Mosquitto instalado no computador, ou um broker público para estudo)
  • Um celular com aplicativo de terminal Bluetooth ou BLE, para os exercícios 4 e 5
  • Protoboard, jumpers, LEDs e resistores
observação

Legenda de estoque. ✅ indica que o item já está no laboratório, com a quantidade entre parênteses. 🛒 indica que ainda precisa ser comprado.

perigo

Nunca escreva senhas de WiFi, tokens ou credenciais diretamente em arquivos que serão enviados ao GitHub. Use placeholders como SUA_REDE e SUA_SENHA nos exemplos e mantenha as credenciais reais em um arquivo ignorado pelo .gitignore, como ensinado no módulo de Versionamento.

aviso

Os módulos de rádio (LoRa, RF 433 MHz e WiFi) devem respeitar as faixas de frequência permitidas na sua região. Confirme a faixa antes de transmitir, e nunca use antenas ou potências além do que a regulamentação permite.

📝 Lista de Exercícios​

Exercício 1: Comunicação serial entre dois pinos UART do ESP32​

Objetivo: entender a comunicação UART, usando a porta serial de hardware (Serial2) em um teste de loopback.

Materiais: ESP32 DEVKIT ✅ (5), fio jumper ✅ (protoboard ✅ (21)).

Roteiro:

  1. Ligue o pino TX2 (GPIO 17) ao pino RX2 (GPIO 16) com um jumper.
  2. Envie uma mensagem pela Serial2 e leia de volta a mesma mensagem.
  3. Compare a mensagem recebida com a enviada e altere a velocidade (baud rate) para ver o efeito.
💡 Ver Resolução / Gabarito
void setup() {
  Serial.begin(115200);
  Serial2.begin(9600, SERIAL_8N1, 16, 17);   // RX2 = 16, TX2 = 17
}

void loop() {
  Serial2.println("teste UART");
  delay(500);
  while (Serial2.available()) {
    Serial.write(Serial2.read());
  }
}

Os parâmetros SERIAL_8N1 indicam 8 bits de dados, sem paridade e 1 bit de parada. Esse formato é o padrão mais usado em UART.

Exercício 2: Barramento I2C com display OLED SSD1306​

Objetivo: encontrar o endereço de dispositivos I2C com um scanner e escrever texto em um display OLED.

Materiais: ESP32 DEVKIT ✅ (5), display OLED SSD1306 ✅ (1, ideal 5), resistores de pull-up 4,7kΩ ✅ (68) × 2 (se o módulo não tiver).

Roteiro:

  1. Ligue SDA ao GPIO 21 e SCL ao GPIO 22 (pinos padrão de I2C no ESP32 DEVKIT).
  2. Rode um scanner de I2C e anote o endereço do display (normalmente 0x3C).
  3. Escreva "Olá, I2C!" no display com a biblioteca Adafruit SSD1306.
💡 Ver Resolução / Gabarito
#include <Wire.h>
#include <Adafruit_GFX.h>
#include <Adafruit_SSD1306.h>

Adafruit_SSD1306 oled(128, 64, &Wire, -1);

void setup() {
  Serial.begin(115200);
  Wire.begin(21, 22);

  for (byte e = 1; e < 127; e++) {        // scanner de I2C
    Wire.beginTransmission(e);
    if (Wire.endTransmission() == 0) Serial.printf("Dispositivo em 0x%02X\n", e);
  }

  oled.begin(SSD1306_SWITCHCAPVCC, 0x3C);
  oled.clearDisplay();
  oled.setTextSize(1);
  oled.setTextColor(SSD1306_WHITE);
  oled.setCursor(0, 0);
  oled.println("Ola, I2C!");
  oled.display();
}

void loop() {}

O I2C usa apenas dois fios para vários dispositivos, identificados por endereço. Por isso, o scanner é a primeira ferramenta para diagnosticar um dispositivo que não responde.

Exercício 3: Display TFT com barramento SPI​

Objetivo: usar o barramento SPI, mais rápido que o I2C, para atualizar um display colorido.

Materiais: ESP32 DEVKIT ✅ (5), display TFT ST7735 1,8" ✅ (1, ideal 3), fios jumper.

Roteiro:

  1. Ligue SCK ao GPIO 18, MOSI ao GPIO 23, CS ao GPIO 5, DC ao GPIO 4 e RST ao GPIO 16.
  2. Inicialize o display e preencha a tela com três cores diferentes, em sequência.
  3. Desenhe um texto na tela em cada cor.
observação

A biblioteca TFT_eSPI precisa ser configurada para o modelo exato do display. Consulte o arquivo User_Setup.h da biblioteca e ajuste o driver (ST7735) e os pinos antes de compilar.

💡 Ver Resolução / Gabarito
#include <Adafruit_ST7735.h>
#include <Adafruit_GFX.h>
#include <SPI.h>

Adafruit_ST7735 tft(5, 4, 16);   // CS, DC, RST

void setup() {
  tft.initR(INITR_BLACKTAB);
  tft.setRotation(1);
}

void loop() {
  tft.fillScreen(ST77XX_RED);
  tft.setCursor(10, 40);
  tft.setTextColor(ST77XX_WHITE);
  tft.setTextSize(2);
  tft.print("VERMELHO");
  delay(1000);

  tft.fillScreen(ST77XX_GREEN);
  tft.setCursor(10, 40);
  tft.setTextColor(ST77XX_BLACK);
  tft.print("VERDE");
  delay(1000);
}

O SPI é mais rápido que o I2C, mas usa um pino de seleção (CS) para cada dispositivo. Por isso, adicionar um segundo display exige mais um pino.

Exercício 4: Bluetooth Clássico com o módulo HC-05​

Objetivo: criar uma ponte serial entre o celular e o ESP32 usando o módulo HC-05, e controlar um LED por comandos de texto.

Materiais: ESP32 DEVKIT ✅ (5), módulo Bluetooth HC-05 ✅ (2, ideal 2), LED verde ✅ (40), resistor 220Ω ✅ (127), divisor de tensão no RX do HC-05 se o módulo for de 5 V.

Roteiro:

  1. Ligue o TX do HC-05 ao RX2 do ESP32 (GPIO 16) e o RX do HC-05 ao TX2 (GPIO 17). Alimente o HC-05 em 3,3 V ou 5 V, conforme o módulo.
  2. Pareie o celular com o HC-05 e abra um aplicativo de terminal serial.
  3. Envie L para acender o LED e D para apagá-lo.
aviso

A maioria dos módulos HC-05 usa lógica de 3,3 V, mas alguns são de 5 V. Confira a placa antes de ligar, pois aplicar 5 V no RX do ESP32 pode danificá-lo.

💡 Ver Resolução / Gabarito
const int PINO_LED = 26;

void setup() {
  Serial.begin(115200);
  Serial2.begin(9600, SERIAL_8N1, 16, 17);   // HC-05 nos pinos 16 e 17
  pinMode(PINO_LED, OUTPUT);
}

void loop() {
  if (Serial2.available()) {
    char c = Serial2.read();
    if (c == 'L') digitalWrite(PINO_LED, HIGH);
    if (c == 'D') digitalWrite(PINO_LED, LOW);
    Serial.printf("Recebido: %c\n", c);
  }
}

O HC-05 é um módulo de Bluetooth Clássico, e a velocidade padrão costuma ser 9600 bps. Ele se comporta como um cabo serial sem fio.

Exercício 5: BLE com o Bluetooth nativo do ESP32​

Objetivo: criar um servidor BLE com uma característica de leitura e escrita, usando o rádio Bluetooth integrado, sem módulo externo.

Materiais: ESP32 DEVKIT ✅ (5), LED vermelho ✅ (45), resistor 220Ω ✅ (127), celular com aplicativo BLE (como um scanner de BLE).

Roteiro:

  1. Crie um serviço BLE com uma característica que aceita escrita. O celular escreve 1 para acender o LED e 0 para apagá-lo.
  2. Crie outra característica de leitura que informa o tempo ligado do ESP32 em segundos.
  3. Use um aplicativo de BLE para conferir o nome do dispositivo e as características criadas.
💡 Ver Resolução / Gabarito
#include <BLEDevice.h>
#include <BLEServer.h>
#include <BLEUtils.h>

#define SERVICO_UUID   "12345678-1234-1234-1234-123456789abc"
#define CONTROLE_UUID  "12345678-1234-1234-1234-123456789abd"
#define TEMPO_UUID     "12345678-1234-1234-1234-123456789abe"

const int PINO_LED = 26;
BLECharacteristic *caracTempo;

class AoEscrever : public BLECharacteristicCallbacks {
  void onWrite(BLECharacteristic *c) override {
    String valor = c->getValue();
    digitalWrite(PINO_LED, valor == "1");
  }
};

void setup() {
  Serial.begin(115200);
  pinMode(PINO_LED, OUTPUT);

  BLEDevice::init("ESP32-Laboratorio");
  BLEServer *servidor = BLEDevice::createServer();
  BLEService *servico = servidor->createService(SERVICO_UUID);

  BLECharacteristic *controle = servico->createCharacteristic(
    CONTROLE_UUID, BLECharacteristic::PROPERTY_WRITE);
  controle->setCallbacks(new AoEscrever());

  caracTempo = servico->createCharacteristic(
    TEMPO_UUID, BLECharacteristic::PROPERTY_READ);

  servico->start();
  BLEDevice::getAdvertising()->start();
}

void loop() {
  caracTempo->setValue(String(millis() / 1000).c_str());
  delay(1000);
}

Os UUIDs identificam serviços e características. Gere os seus com um gerador de UUID, para não conflitar com outros dispositivos.

Exercício 6: Conexão WiFi e requisição HTTP​

Objetivo: conectar o ESP32 a uma rede WiFi e fazer uma requisição HTTP GET a um serviço da internet.

Materiais: ESP32 DEVKIT ✅ (5), rede WiFi do laboratório, monitor serial.

Roteiro:

  1. Conecte-se à sua rede usando as variáveis SSID e SENHA, preenchidas com placeholders no arquivo versionado.
  2. Aguarde a conexão e imprima o endereço IP obtido.
  3. Faça uma requisição HTTP GET a um endereço de teste e imprima o código de resposta.
perigo

Não grave o nome e a senha da sua rede no código que vai ao GitHub. Substitua por SUA_REDE e SUA_SENHA no arquivo compartilhado.

💡 Ver Resolução / Gabarito
#include <WiFi.h>
#include <HTTPClient.h>

const char *SSID = "SUA_REDE";
const char *SENHA = "SUA_SENHA";

void setup() {
  Serial.begin(115200);
  WiFi.begin(SSID, SENHA);

  Serial.print("Conectando");
  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
    Serial.print(".");
  }
  Serial.println();
  Serial.println(WiFi.localIP());

  HTTPClient http;
  http.begin("http://example.com/");
  int codigo = http.GET();
  Serial.printf("Resposta HTTP: %d\n", codigo);
  http.end();
}

void loop() {}

Este exercício usa delay() na espera pela conexão, o que é aceitável aqui. Em um projeto real, use a verificação de tempo do submódulo de Programação Não Bloqueante.

Exercício 7: Servidor web para controlar um relé e ler um sensor​

Objetivo: criar uma página web no próprio ESP32 com um botão para acionar um relé e a leitura de temperatura e umidade.

Materiais: ESP32 DEVKIT ✅ (5), sensor DHT11 ✅ (11), relé 5 V ✅ (5, ideal 4,5), transistor BC548 ✅ (3, ideal 10), diodo 1N4007 ✅ (41), resistor 1kΩ ✅ (199), rede WiFi do laboratório.

Roteiro:

  1. Conecte-se à rede WiFi (com placeholders) e inicie um servidor web na porta 80.
  2. Crie uma rota / que mostra a temperatura e a umidade do DHT11, e um botão que aponta para /rele.
  3. Na rota /rele, inverta o estado do relé e redirecione para a página principal.
💡 Ver Resolução / Gabarito
#include <WiFi.h>
#include <WebServer.h>
#include <DHT.h>

const char *SSID = "SUA_REDE";
const char *SENHA = "SUA_SENHA";
const int PINO_RELE = 26;
DHT dht(15, DHT11);
WebServer servidor(80);
bool releLigado = false;

void paginaPrincipal() {
  String html = "<h1>Laboratorio</h1>";
  html += "<p>Temperatura: " + String(dht.readTemperature()) + " C</p>";
  html += "<p>Umidade: " + String(dht.readHumidity()) + " %</p>";
  html += "<a href='/rele'><button>Alternar rele</button></a>";
  servidor.send(200, "text/html", html);
}

void alternarRele() {
  releLigado = !releLigado;
  digitalWrite(PINO_RELE, releLigado);
  servidor.sendHeader("Location", "/");
  servidor.send(303);
}

void setup() {
  Serial.begin(115200);
  pinMode(PINO_RELE, OUTPUT);
  dht.begin();
  WiFi.begin(SSID, SENHA);
  while (WiFi.status() != WL_CONNECTED) delay(500);
  Serial.println(WiFi.localIP());

  servidor.on("/", paginaPrincipal);
  servidor.on("/rele", alternarRele);
  servidor.begin();
}

void loop() {
  servidor.handleClient();
}

Acesse o IP impresso no monitor serial em um navegador da mesma rede. O relé só deve ser ligado com o circuito de transistor e diodo, como no exercício 15 do submódulo de GPIOs Digitais.

Exercício 8: Telemetria com MQTT e o sensor DS18B20​

Objetivo: publicar leituras de temperatura em um broker MQTT, o protocolo mais usado em IoT para mensagens leves.

Materiais: ESP32 DEVKIT ✅ (5), sensor DS18B20 ✅ (1, ideal 5), resistor 4,7kΩ ✅ (68) (pull-up), broker Mosquitto no computador ou broker público para estudo, rede WiFi do laboratório.

Roteiro:

  1. Instale o broker Mosquitto no computador, ou use um broker de estudo. Anote o endereço e a porta 1883.
  2. Conecte o ESP32 à rede e ao broker com a biblioteca PubSubClient.
  3. Publique a temperatura no tópico laboratorio/sala1/temperatura a cada 10 segundos.
  4. Use um cliente MQTT no computador (como o mosquitto_sub) para assinar o tópico e confirmar as mensagens.
aviso

Brokers públicos não são privados: qualquer pessoa pode assinar os tópicos. Use-os só com dados de teste e nunca publique informações pessoais ou sensíveis.

💡 Ver Resolução / Gabarito
#include <WiFi.h>
#include <PubSubClient.h>
#include <OneWire.h>
#include <DallasTemperature.h>

const char *SSID = "SUA_REDE";
const char *SENHA = "SUA_SENHA";
const char *BROKER = "192.168.0.10";    // IP do computador com Mosquitto
const int PORTA = 1883;

OneWire barramento(15);
DallasTemperature ds(&barramento);
WiFiClient redeCliente;
PubSubClient mqtt(redeCliente);

void conectarMqtt() {
  while (!mqtt.connected()) {
    if (mqtt.connect("esp32-sala1")) {
      Serial.println("MQTT conectado");
    } else {
      delay(2000);
    }
  }
}

void setup() {
  Serial.begin(115200);
  ds.begin();
  WiFi.begin(SSID, SENHA);
  while (WiFi.status() != WL_CONNECTED) delay(500);
  mqtt.setServer(BROKER, PORTA);
}

void loop() {
  if (!mqtt.connected()) conectarMqtt();
  mqtt.loop();

  static unsigned long ultimo = 0;
  if (millis() - ultimo >= 10000) {
    ultimo = millis();
    ds.requestTemperatures();
    String msg = String(ds.getTempCByIndex(0), 2);
    mqtt.publish("laboratorio/sala1/temperatura", msg.c_str());
    Serial.println("Publicado: " + msg);
  }
}

Use mqtt.loop() em toda volta do loop(). Ele mantém a conexão viva e processa mensagens recebidas.

Exercício 9: Comunicação direta entre dois ESP32 com ESP-NOW​

Objetivo: enviar mensagens diretamente entre dois ESP32, sem roteador e sem conexão WiFi, usando o protocolo ESP-NOW.

Materiais: ESP32 DEVKIT ✅ (5) × 2, LED verde ✅ (40), botão sem retenção ✅ (55), resistor 220Ω ✅ (127).

Roteiro:

  1. No primeiro ESP32, descubra o endereço MAC com WiFi.macAddress() e anote.
  2. No segundo ESP32, configure o ESP-NOW e registre o MAC do primeiro como par.
  3. No primeiro, envie a mensagem 1 ao pressionar o botão. No segundo, acenda o LED ao receber 1.
💡 Ver Resolução / Gabarito

Transmissor (primeiro ESP32):

#include <WiFi.h>
#include <esp_now.h>

uint8_t receptor[] = {0x24, 0x6F, 0x28, 0xAA, 0xBB, 0xCC};   // MAC do receptor

void setup() {
  WiFi.mode(WIFI_STA);
  esp_now_init();
  esp_now_peer_info_t par = {};
  memcpy(par.peer_addr, receptor, 6);
  par.channel = 0;
  par.encrypt = false;
  esp_now_add_peer(&par);
  pinMode(4, INPUT_PULLUP);
}

void loop() {
  if (digitalRead(4) == LOW) {
    uint8_t msg = 1;
    esp_now_send(receptor, &msg, 1);
    delay(300);
  }
}

Receptor (segundo ESP32):

#include <WiFi.h>
#include <esp_now.h>

const int PINO_LED = 26;

void aoReceber(const esp_now_recv_info_t *info, const uint8_t *dados, int len) {
  if (len > 0 && dados[0] == 1) digitalWrite(PINO_LED, !digitalRead(PINO_LED));
}

void setup() {
  pinMode(PINO_LED, OUTPUT);
  WiFi.mode(WIFI_STA);
  esp_now_init();
  esp_now_register_recv_cb(aoReceber);
}

void loop() {}

Substitua o MAC de exemplo pelo MAC real do receptor. ESP-NOW dispensa roteador, mas os dois dispositivos precisam estar no mesmo canal de WiFi.

Exercício 10: Comunicação de longo alcance com LoRa​

Objetivo: enviar leituras por rádio LoRa, que alcança distâncias muito maiores que o WiFi, com baixo consumo.

Materiais: módulo LoRa padrão ✅ (1, ideal 0), módulo LoRa SX1278 🛒 (ideal 5) para o segundo nó, sensor DHT11 ✅ (11), antenas incluídas no módulo, ESP32 DEVKIT ✅ (5) × 2.

Roteiro:

  1. Ligue o módulo LoRa ao ESP32 com SPI (SCK 18, MISO 19, MOSI 23) e os pinos NSS 5, RST 14 e DIO0 2.
  2. No transmissor, envie a temperatura do DHT11 a cada 5 segundos, em um pacote de texto.
  3. No receptor, leia o pacote e imprima o valor e a intensidade do sinal (RSSI).
observação

Os dois nós precisam estar na mesma frequência e com o mesmo fator de espalhamento. Confira a frequência permitida na sua região antes de transmitir.

💡 Ver Resolução / Gabarito

Transmissor:

#include <SPI.h>
#include <LoRa.h>
#include <DHT.h>

DHT dht(15, DHT11);

void setup() {
  Serial.begin(115200);
  dht.begin();
  LoRa.setPins(5, 14, 2);            // NSS, RST, DIO0
  if (!LoRa.begin(915E6)) {          // ajuste à frequência permitida
    Serial.println("Falha no LoRa");
    while (1);
  }
}

void loop() {
  String msg = "T=" + String(dht.readTemperature(), 1);
  LoRa.beginPacket();
  LoRa.print(msg);
  LoRa.endPacket();
  Serial.println("Enviado: " + msg);
  delay(5000);
}

Receptor:

#include <SPI.h>
#include <LoRa.h>

void setup() {
  Serial.begin(115200);
  LoRa.setPins(5, 14, 2);
  LoRa.begin(915E6);
}

void loop() {
  int tamanho = LoRa.parsePacket();
  if (tamanho) {
    String msg = "";
    while (LoRa.available()) msg += (char)LoRa.read();
    Serial.printf("Recebido: %s  RSSI=%d\n", msg.c_str(), LoRa.packetRssi());
  }
}

O RSSI é a intensidade do sinal recebido, em dBm. Valores mais negativos indicam sinal mais fraco.

Exercício 11: Controle remoto por RF 433 MHz​

Objetivo: enviar e receber códigos de controle remoto simples com módulos RF de 433 MHz, sem protocolo de rede.

Materiais: módulo RF transmissor e receptor 433 MHz ✅ (4, ideal 4), ESP32 DEVKIT ✅ (5) × 2, LED verde ✅ (40), resistor 220Ω ✅ (127), biblioteca RCSwitch.

Roteiro:

  1. No transmissor, ligue o pino de dados a GPIO 25 e envie um código de 24 bits a cada pressionamento de botão.
  2. No receptor, ligue a saída de dados a GPIO 26 e acenda o LED quando o código correto chegar.
  3. Teste com um código errado e confirme que o LED não reage.
💡 Ver Resolução / Gabarito

Transmissor:

#include <RCSwitch.h>

RCSwitch transmissor = RCSwitch();

void setup() {
  transmissor.enableTransmit(25);
}

void loop() {
  transmissor.send(5393, 24);   // código de 24 bits
  delay(1000);
}

Receptor:

#include <RCSwitch.h>

RCSwitch receptor = RCSwitch();
const int PINO_LED = 27;

void setup() {
  Serial.begin(115200);
  pinMode(PINO_LED, OUTPUT);
  receptor.enableReceive(26);
}

void loop() {
  if (receptor.available()) {
    unsigned long codigo = receptor.getReceivedValue();
    Serial.println(codigo);
    digitalWrite(PINO_LED, codigo == 5393);
    receptor.resetAvailable();
  }
}

Módulos RF 433 MHz são baratos, mas não têm confirmação de recebimento nem criptografia. Use-os para controle simples, nunca para ações de segurança.

Exercício 12: Localização com o GPS NEO-6M​

Objetivo: ler sentenças NMEA de um receptor GPS e extrair latitude, longitude e altitude.

Materiais: módulo GPS NEO-6M 🛒 (ideal 5), módulo LoRa com GPS ✅ (1, ideal 0) como alternativa, ESP32 DEVKIT ✅ (5), antena do GPS, biblioteca TinyGPSPlus.

Roteiro:

  1. Ligue a saída TX do GPS ao RX2 do ESP32 (GPIO 16). Alimente o GPS em 3,3 V ou 5 V, conforme o módulo.
  2. Leia os caracteres com Serial2 e alimente o objeto TinyGPSPlus.
  3. Imprima a latitude, longitude e altitude sempre que a posição for atualizada.
  4. Leve o módulo para um local aberto. A primeira fixação pode levar alguns minutos.
observação

O NEO-6M transmite sentenças NMEA em texto. A biblioteca TinyGPSPlus faz a interpretação e informa se a posição é válida.

💡 Ver Resolução / Gabarito
#include <TinyGPSPlus.h>

TinyGPSPlus gps;

void setup() {
  Serial.begin(115200);
  Serial2.begin(9600, SERIAL_8N1, 16, 17);   // RX2 = 16 recebe do GPS
}

void loop() {
  while (Serial2.available()) {
    gps.encode(Serial2.read());
  }

  if (gps.location.isUpdated()) {
    Serial.printf("Lat: %.6f  Lon: %.6f  Alt: %.1f m  Sat: %d\n",
                  gps.location.lat(), gps.location.lng(),
                  gps.altitude.meters(), gps.satellites.value());
  }
}

Enquanto o GPS não tiver fixação, gps.location.isValid() retorna falso. Não use as coordenadas antes disso.

Exercício 13: Comandos AT com o módulo ESP-01​

Objetivo: controlar um módulo WiFi ESP-01 por comandos AT pela porta serial, e entender como um microcontrolador pode ser ponte de comunicação.

Materiais: módulo ESP-01 ✅ (2, ideal 0), ESP8266 ✅ (2, ideal 0), ESP32 DEVKIT ✅ (5), conversor USB-serial ou alimentação de 3,3 V estável (o ESP-01 consome picos de corrente), resistores de divisão se necessário.

Roteiro:

  1. Ligue o ESP-01 ao ESP32: TX do ESP-01 no RX2 do ESP32 (GPIO 16), RX do ESP-01 no TX2 (GPIO 17). Alimente o ESP-01 em 3,3 V com corrente suficiente.
  2. Envie AT e confirme a resposta OK.
  3. Envie AT+GMR para ver a versão do firmware.
  4. Conecte à rede com AT+CWJAP="SUA_REDE","SUA_SENHA" (use placeholders no arquivo versionado).
aviso

O ESP-01 pode consumir até 300 mA em picos, e a alimentação do ESP32 não deve ser usada para isso. Use uma fonte de 3,3 V separada, com capacitor de 100uF ✅ (29) na alimentação do módulo.

💡 Ver Resolução / Gabarito
void enviarAT(const char *comando, unsigned long espera = 1000) {
  Serial2.println(comando);
  unsigned long inicio = millis();
  while (millis() - inicio < espera) {
    while (Serial2.available()) Serial.write(Serial2.read());
  }
}

void setup() {
  Serial.begin(115200);
  Serial2.begin(115200, SERIAL_8N1, 16, 17);
  delay(1000);
  enviarAT("AT");
  enviarAT("AT+GMR");
  enviarAT("AT+CWJAP=\"SUA_REDE\",\"SUA_SENHA\"", 8000);
}

void loop() {
  while (Serial.available()) Serial2.write(Serial.read());   // ponte: PC -> ESP-01
  while (Serial2.available()) Serial.write(Serial2.read());  // ponte: ESP-01 -> PC
}

O conjunto de comandos AT é o mesmo usado em módulos ESP8266 e ESP-01. Após conectar, o módulo pode ser controlado por comandos como AT+CIPSTART para abrir conexões TCP.

Exercício 14: Streaming de vídeo com a ESP32 CAM​

Objetivo: transmitir imagens da câmera da ESP32 CAM por WiFi, em um servidor de vídeo MJPEG acessível por navegador.

Materiais: ESP32 CAM ✅ (6, ideal 5), adaptador USB-serial (FTDI ou conversor equivalente) 🛒, LED de iluminação da câmera (LED interno da placa), rede WiFi do laboratório.

Roteiro:

  1. Conecte o adaptador USB-serial: TX ao U0R, RX ao U0T, GND e 5 V. Para gravar, ligue GPIO 0 ao GND e pressione reset.
  2. Abra o exemplo CameraWebServer na IDE, escolha o modelo CAMERA_MODEL_AI_THINKER e preencha SSID e senha com placeholders.
  3. Grave o programa, desconecte GPIO 0 do GND, reinicie a placa e acesse o IP no navegador.
  4. Ajuste a resolução e a qualidade da imagem pela página do servidor e observe o impacto na fluidez.
perigo

A ESP32 CAM não tem regulador de tensão robusto. Alimente-a com 5 V de fonte estável, pois quedas de tensão causam reinicializações. Desconecte GPIO 0 do GND após a gravação, senão a placa não inicia o programa.

O exemplo oficial CameraWebServer tem o código completo. Os trechos relevantes são a escolha do modelo da câmera e a conexão WiFi:

  WiFi.begin(ssid, password);
  while (WiFi.status() != WL_CONNECTED) delay(500);
  Serial.println(WiFi.localIP());
  // inicialização da câmera e do servidor fica no exemplo oficial
}

O MJPEG envia uma sequência de imagens JPEG em um único fluxo HTTP. Por isso, o navegador mostra o vídeo sem plugins. A resolução maior exige mais memória e reduz a taxa de quadros.
